# Обновление часов: состояние и запуск

Это Rust/Rhai-система для ESP32-S3 N4R2, экран ST7789V3 240×280.
Она использует оформление по предоставленным фотографиям, но не запускает
Android/Wear OS, APK или сервисы Google. Язык по умолчанию — русский.

## Выполнено по списку

| № | Состояние |
|---|---|
| 1 | При таймауте 30 с затемнение начинается на 20-й секунде, за 500 мс достигает 15%, экран выключается на 30-й. Можно выбрать 1–10 минут. Первое действие только пробуждает экран. |
| 2 | Программная ШИМ GPIO6 удалена: включённая подсветка получает постоянный уровень. Яркость изменяется масштабированием RGB565. Мерцание самой матрицы/питания этим не измерено и требует проверки часов. |
| 3 | Добавлены переходы страниц, анимированная заставка, плавное затемнение, секундная стрелка и индикатор реального воспроизведения при наличии данных компаньона. Неизменившиеся кадры не отправляются на экран. |
| 4 | Меню питания: выключение, перезагрузка, циферблат, Recovery, Fastboot. Удержание кнопки от 3,5 с открывает меню. Режим загрузки передаётся через RTC RAM. Выключение — deep sleep с пробуждением GPIO13. Recovery/Fastboot имеют собственные экраны с управлением колёсиком. Это не стандартный Android USB Fastboot и не полноценное Android Recovery. |
| 5 | Убраны подписи состояния радиокнопок на основном циферблате; состояние передаётся цветом значков. |
| 6 | Три варианта: цифровой с двумя строками времени, аналоговый со стрелками, прежний с компликациями. Выбор: Настройки → Экран → Циферблат. Показания здоровья/погоды не выдумываются. |
| 7 | Цветная анимированная заставка с надписью `AOSP Wear / by AOSP`. |
| 8 | Надпись «Устройство подключено». Кнопка Pause и прогресс зависят от принятого состояния; нажатие HID Play/Pause само по себе не доказывает начало воспроизведения. Для автоматических данных с телефона пока требуется отдельное приложение-компаньон. |
| 9 | Сглаживание границ окружностей, колец и скруглённых карточек, официальные сглаженные Roboto и Material Symbols. Физическое разрешение остаётся 240×280. |
| 10 | Из раздела «Часы» будильник, таймер и секундомер открываются напрямую без повторного выбора. |
| 11 | Импорт PNG/JPEG через компьютер в образ карты, проверка размеров и CRC, переключатель обоев в настройках экрана. Загрузка с самого телефона не реализована. |
| 12 | GPT уже содержит заданные 13 разделов; образ на 512 МиБ проверен. `userdata` получает остаток около 265 МиБ. |
| 13 | Расширен локальный ZADB: состояние, ввод, перезагрузка в режимы, выключение, снимок экрана и обновление обоев. Это ограниченные команды, не произвольная Unix-оболочка/стандартный Android ADB. |
| 14 | Ассистент отправляет Consumer Voice Command (0xCF) сопряжённому зашифрованному HID-устройству. ОС телефона выбирает обработчик; Gemini должен быть установлен как ассистент по умолчанию. Проверка на телефоне ещё нужна, принудительный запуск конкретного приложения не реализован. |
| 15 | Интеграция с приложением Google Pixel Watch не реализована: здесь отсутствуют Android/Wear/GMS-службы сопряжения. Настройка подключения эмулятора не заменяет эти службы. |
| 16 | Bluetooth Classic/A2DP отсутствует в ESP32-S3. Подключение обычных наушников для звука и музыки не реализовано. LE Audio также не реализован. |
| 17 | Полноценный браузер с YouTube/Telegram и видео не реализован. Для такого режима нужен отдельный браузер на телефоне/ПК и транспорт изображения/ввода; в текущей прошивке этого транспорта нет. |

Постоянная подсветка устраняет именно программные импульсы BLK. Промежуточная
яркость теперь уменьшает светлость пикселей, а не ток подсветки: на LCD это
ухудшает контраст и не экономит её питание. При выключении GPIO6 действительно
становится низким. Для аналогового регулирования нужен подходящий драйвер LED.

## Сборка и microSD

Остановите сервер PC block (Ctrl+C в его терминале), если он обслуживает образ,
который собираетесь пересобрать. Сборщик сохраняет пользовательские разделы
совместимого образа и отказывается менять занятый образ или его размер.

Из корня проекта:

```sh
cd /home/denis/Developer/Android-For-ESP32S3
./flash sd --build-only
lsblk -o NAME,SIZE,MODEL,MOUNTPOINTS
```

Выберите **всю карту**, например `/dev/sdX`, и размонтируйте её смонтированные
разделы. Следующая команда полностью заменяет содержимое выбранного диска.
`/dev/sdX` — заполнитель, его необходимо заменить своим устройством.

```sh
sudo dd if=Firmware/out/target/product/zero/aosp-wear-sd.img of=/dev/sdX bs=4M status=progress conv=fsync
sync
```

После `sync` извлеките карту из USB-картридера и вставьте её в слот часов.
Затем выполните:

```sh
./flash sd
```

Компьютер не передаёт содержимое `/dev/sdX` через кабель часов
в режиме SD: карта должна быть физически доступна ESP32 по SPI.

Последняя команда прошивает внутреннее приложение ESP32 и открывает монитор.
Системные данные загружаются с карты; Ctrl+C закрывает монитор, часы продолжают
работать. `./flash pc` выбирает хранение на ПК и запускает сервер.
Ни карта, ни подключённые часы в ходе этой работы автоматически не прошивались.

Отдельный проверенный свежий образ:
`Firmware/out/restored-sd512/aosp-wear-sd.img`. Его можно использовать вместо
образа по умолчанию в команде `dd`; он содержит чистые пользовательские данные.

## Обои и снимок экрана

Нужны ImageMagick и Python с pyserial. Остановите сервер, выполняйте из Bootloader:

```sh
python tools/watch_assets.py --image ../Firmware/out/target/product/zero/aosp-wear-sd.img wallpaper /путь/к/фото.jpg
```

Фото автоматически обрезается по центру до 240×280 и переводится в RGB565.
При следующей загрузке оно применяется к циферблату. Для физической SD используйте
образ с добавленными обоями перед его записью на карту. Прямое редактирование
устройства `/dev/sdX` этим инструментом не поддерживается.

При работающем сервере:

```sh
python zadb.py shell help
python zadb.py shell state
python zadb.py shell rotate 1
python zadb.py shell screencap
python zadb.py shell wallpaper-reload
python zadb.py shell power-menu
python zadb.py shell reboot recovery
```

Чтобы сохранить **уже полученный** снимок, остановите сервер и выполните:

```sh
python tools/watch_assets.py --image ../Firmware/out/target/product/zero/aosp-wear-sd.img screenshot watch.png
```

Команды используют локальный Unix-сокет сервера в PC-режиме. При автономной
работе от SD этот CLI сам по себе USB-транспорт не открывает. Снимок/обои/переход
в режим через shell запрещены, если часы заблокированы PIN.

## Протокол состояния медиаплеера для компаньона

После BLE-сопряжения и включения шифрования доступен необязательный сервис:

- service UUID: `3c7e0001-3b14-4a80-9d3f-178b14740001`;
- writable characteristic UUID: `3c7e0002-3b14-4a80-9d3f-178b14740001`;
- ровно 20 байт: `[version=1, state, position_ms:u32LE, duration_ms:u32LE, reserved:10]`;
- `state`: 0 — остановлено, 1 — пауза, 2 — воспроизведение;
- `position <= duration <= 604800000`; неиспользуемые байты передавайте нулями;
- обновление при изменении состояния и хотя бы каждые 15 с. Через 30 с без данных
  состояние устаревает; отключение Bluetooth сразу его сбрасывает.

Часы экстраполируют позицию только во время полученного состояния «играет»,
останавливают её на конце трека и не меняют её оптимистически по кнопке HID.
Это реализованный интерфейс прошивки, а не готовое приложение Android:
для передачи MediaSession телефона нужен компаньон с разрешением доступа
к уведомлениям/медиасессиям. Название песни и аудиопоток здесь не передаются.

Связь Voice Command с системным ассистентом опирается на
[Linux HID mapping](https://github.com/torvalds/linux/blob/master/drivers/hid/hid-input.c)
и [Android Generic.kl](https://android.googlesource.com/platform/frameworks/base/+/refs/heads/main/data/keyboards/Generic.kl).

## Проверки и ограничения

Сборки release PC/HID и SD/HID проходят без предупреждений компилятора/линкера.
20 host-тестов проверяют настоящий runtime/Rhai, графику, ввод, таймеры, PIN,
питание и прогресс медиаплеера. Отдельно проверены сохранение пользовательских
разделов при пересборке, границы записи обоев и GPT/AVB/CPIO/liblp образа SD.
Превью получено тем же RGB565-рендерером, что используется на экране часов.

Физическая проверка новой версии ещё нужна для мерцания, цветов, deep sleep,
SD-шины, BLE-сопряжения и запуска ассистента. Проверки на компьютере не заменяют
эти испытания. PIN — локальная блокировка интерфейса, а не аппаратная защита
от перепрошивки/извлечения карты.

## Если после записи появляется `android boot error: Card`

В старом логе эта ошибка означала сбой инициализации/получения ёмкости карты
ещё до чтения GPT, а не доказанное отсутствие системы. Успешные `dd` и
`Flashing has completed!` относятся соответственно к записи карты на ПК
и к записи приложения ESP32; они не проверяют чтение карты через слот часов.

Теперь загрузчик сохраняет точную ошибку `SdInit(...)`, выводит каждую из трёх
попыток инициализации, а при успехе — ёмкость и тип карты. Ошибка загрузки
разделов отдельно отмечается как `SD GPT ERROR`. Повторы ограничены и происходят
до операций с A/B-метаданными. Первопричина физического сбоя ещё не установлена.

Для диагностики уже записанную карту повторно стирать не нужно. Карта должна
быть в часах, часы подключены к компьютеру по USB, монитор/сервер из предыдущего
запуска закрыт:

```sh
cd /home/denis/Developer/Android-For-ESP32S3
AOSP_WEAR_SKIP_FIRMWARE_BUILD=1 ./flash sd
```

Сохраните строки от `microSD:` до `android boot error:`. `CardNotFound` или
таймаут команды не различают пустой слот, контакт, питание и распиновку;
`CrcError` и `Transport` указывают на другие ошибки обмена. Не отключайте CRC
и не форматируйте карту в FAT32 для обхода ошибки: загрузчик читает GPT-образ.
Проводка этой сборки: MISO/DO → GPIO7, SCK/CLK → GPIO8,
MOSI/DI → GPIO9, CS → GPIO10; общий GND, питание согласно модулю/слоту.
Несовпадение распиновки с физическими соединениями требует изменения конфигурации.
