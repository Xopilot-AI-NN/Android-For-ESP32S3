# 2026-11-04: Air Keyboard — программный стенд без MPU6050

Добавлено приложение **Air Keyboard**, стабильный ID 32. Каталоги Rust/Rhai,
manifest, сборщик пакетов и оба меню согласованы: 22 приложения в launcher.
MPU6050 у пользователя ещё не установлен; выводы 14/15/16 не инициализируются.
Ввод сейчас явно помечен как **тест энкодером**, это не пространственный трекинг.

- Full показывает компактную RU/EN-раскладку и символы; Inline — многострочный
  редактор с подсвеченной временной буквой непосредственно у каретки.
- Модель хранит только подтверждённый UTF-8-текст, до 1024 байт. Есть вставка
  по каретке, Backspace, пробел, Enter, Tab и стрелки по Unicode-кодовым точкам.
  Повторные down-сигналы без release не добавляют второй символ.
- Через меню сохраняются вид/язык в `/AirKeyboard.cfg`; создание
  `/AirKeyboard.txt` экспортирует только подтверждённые байты и не заменяет
  существующий файл. Выход/переход к сопряжению с текстом требуют подтверждения.
- Локальный, BLE HID и совместный вывод используют существующий защищённый
  клавиатурный сервис. Отправка включается отдельно, не сохраняется и сбрасывается
  при закрытии/разрыве Bluetooth. Русские буквы преобразуются в физические
  ЙЦУКЕН-коды: раскладка принимающей ОС должна совпадать. «В очереди» не означает
  подтверждение доставки. Обратной синхронизации текста с ПК нет.

Не реализованы чтение/логирование IMU, распознавание толчка и возврата, качество
трекинга, IMU-калибровка, XYZ/гироскопическое наведение и BLE-мышь. Пороги жестов
без реальных трасс не задавались. Это этап 1 концепции, **не готовая v1**.

Проверено: **128 Rust host-тестов** с новым чистым образом, **4 проверки пакетов**,
инспекция GPT/A-B/CPIO/AVB, release ESP32-S3 и настоящий RGB565-предпросмотр.
Размер приложения: **2 662 256 / 4 128 768 байт (64,48%)**.
Запас стека на проверяемой main/disk/redraw-цепочке: **49 132 байта**;
минимум проверки — 32 КиБ, остальные пути не являются доказанными этим расчётом.

Артефакты: `Firmware/out/air-keyboard-20261104/firmware.bin` и
`Firmware/out/air-keyboard-20261104/aosp-wear-sd.img` (новый образ 512 МиБ).
Образ собран отдельно; текущий диск пользователя, часы и Blender-файлы не менялись.

# 2026-11-04: второй проход оптимизации и исправлений

- Браузер переносит текст сразу в итоговую разметку и останавливается на лимите
  256 строк. Прежний промежуточный список создавал строки всего абзаца ещё до
  применения лимита; длинные слова также больше не измеряются целиком заранее.
- Выход/смена аккаунта закрывает экран выбора Google Фото и очищает его QR,
  выбранную фотографию и таймер опроса. Раньше режим Picker оставался открытым
  после очистки остальных данных аккаунта.
- RGB565-превью распаковывается прямо в единственный буфер `Vec<u16>` без
  промежуточного `Vec<u8>` и копирования всех пикселей. При 108×80 устранён
  отдельный буфер распакованных байтов размером 17 280 байт; это не измерение
  общего пика heap. Сохраняются предел размера, проверка Adler-32 и длины;
  добавлены проверки base64 padding/неиспользуемых битов и хвоста zlib.
- Пустые снимки кэша Gateway тоже разделяются через Arc: до первой синхронизации
  и на заблокированных экранах больше нет нового пустого Arc на каждом кадре.
- Запоздалый ответ отменённого запроса отклоняется до разбора JSON/картинки.
  Повторная проверка ID перед применением результата сохранена.

Проверено: **121 host-тест Rust**, включая реальный TLS, старые сценарии
отмены/смены страниц, максимум 108×80, повреждённые картинки, длинные ссылки,
выход с экрана Picker и общий пустой кэш. Release ESP32-S3 собран.

Расчётный запас стека на контролируемой main/disk/redraw-цепочке — **60 940 байт**;

# 2026-11-04: память сетевых приложений, браузер и KDE Connect

- Кэш Gateway хранится в `Arc<Cache>`: отрисовка Gmail, контактов, фото,
  поиска и браузера получает общий неизменяемый JSON вместо полной копии дерева.

  ограничения PIN сохраняются. Изменение тела кэша использует copy-on-write.
- При фрагментированном chunked HTTP сначала проверяется полное сообщение,
  затем один раз выделяется буфер точного размера. Обе схемы HTTP-тела возвращают
  ошибку при нехватке памяти; лишние байты после завершающего chunk отвергаются.
- Браузер возвращается на главную при отмене первого запроса, освобождает
  ёмкость истории/разметки при закрытии, показывает прокрутку текущей части
  документа и отмечает недоступные переходы назад/вперёд.
- В списках Gmail, Google-контактов, фото и сообщений есть счётчик выбранной
  строки и полоса прокрутки. Пустые списки получили подписи по приложению.
- KDE-мост не пересылает неизменившуюся порцию SMS каждые 30 секунд. Состояние
  доставки сбрасывается при потере связи/подтверждения; неудачная порция
  допускает повтор. SMS-приёмник разбирает 16-байтовые фрагменты на стеке,
  резервирует ограниченный буфер при начале и освобождает после завершения.

# 2026-11-04: локальный Google Gateway, температура и интерфейсы

- Google Gateway получил `init OAUTH_JSON --local-ip LAN_IP`: публичный домен
  больше не нужен. Поддерживаются Desktop OAuth JSON и Web OAuth JSON с точным
  localhost callback. Приватный CA сохраняется при повторной настройке;
  серверный сертификат содержит SAN с IP и обновляется локально через OpenSSL.
- Часы подключаются по HTTPS к LAN IP, без DNS-запроса для числового адреса.
  Проверка CA, IP/имени и времени остаётся включённой. Google OAuth использует
  отдельный loopback callback. Страница localhost показывает ожидающие запросы
  часов; PKCE, cookie/state и подтверждение аккаунта на часах сохранены.
  Loopback HTTP не обслуживает API устройства и проверяет Host.
- Добавлен драйвер внутреннего температурного датчика ESP32-S3: выбор диапазона,
  заводская eFuse-калибровка, кеширование раз в секунду и ограничение ожидания
  готовности 2 мс. Диагностика показывает `Чип: … °C`; ADB выводит десятые доли
  градуса. Это температура кристалла. Ошибка датчика отображается как отсутствие
  показания, без подстановки вымышленного значения.
- Завершена адаптация интерфейсов под прямоугольные 240×280: единые карточки,
  отступы и фокус, нейтральная тёмная тема с мятным акцентом; обновлены медиаплеер,
  калькулятор, файлы, задачи, часы, календарь, Google, подключение телефона,
  BT-клавиатура и Share. Описание геометрии и правил: `App/WEAR_RECT_DESIGN.md`.
  Основные экраны и четыре темы проверены рендерером; добавлен сценарий температуры.

Проверки: 105 Rust host-тестов, 19 Node-тестов и 6 Python-тестов Gateway проходят.
Настоящие TLS-handshake проверяют SAN с IPv4 и отказ для неверного IP/CA/времени;
OAuth проверен на синтетических данных. Вход в личный Google-аккаунт не выполнялся.
Подробные команды локального запуска и настройки образа: `GoogleAuthGateway/README.md`.
Новые изменения датчика не проверены на плате: USB-устройство сейчас отсутствует.

# 2026-11-03: оптимизация RAM, ZPager и вывода кадров

Внешний вид интерфейса на этом этапе не менялся: 61 кадр контрольного рендерера
совпадает побайтно с предыдущим набором.

- Состояние приложений и кэш Material-кадра размещены в стабильных heap-объектах.
  Кэш кадра переиспользует один объект, не выделяет память при каждом вводе.
  Кадр `init::run` уменьшился с 97232 до 68128 байт. При основном стеке 156060
  байт запас за проверяемой цепочкой init/disk/redraw составляет 81980 байт
  вместо предыдущих 53036. Это запас для вложенных вызовов, а не измерение
  полного худшего случая; аппаратная защита стека остаётся включённой.
- Активные пользовательские обои и их кэш разделяют один RGB565-буфер через Rc.
  Устранена копия 134400 байт (131,25 КиБ). При замене обоев старый буфер освобождается.
- Малые записи ZPager до 496 байт используют секторный буфер 512 байт без heap
  allocation. Для больших записей выделяется только фактически нужное число
  секторов; больше нет отдельного выделения и последующего расширения буфера чтения.
  Формат ZPG1, CRC и расположение слотов сохранены.
- Добавлен фиксированный кэш курсоров 32 системных экранов (136 байт данных):
  повторные переходы не читают страницу заново и не пишут неизменный курсор.
  Ошибки транспорта не кэшируются; настройка PIN, аккаунты и файлы через этот
  кэш не проходят. Постоянные записи по-прежнему сохраняются синхронно.
- Сравнение кадров идёт по строкам. Разнесённые изменения передаются отдельными
  полосами с ограничением 18 окон; для плотного изменения выбирается одно окно.
  В предыдущем кадре копируются только переданные участки, а не весь буфер
  134400 байт. После ошибки SPI предыдущий кадр инвалидируется для полного восстановления.
- Исправлено перемежение управляющих команд и заголовков USB PC-диска:
  команда, пришедшая перед DATA/OK, ставится в очередь вместо ошибки диска.
  Частично прочитанный префикс команды сохраняется при переходе к дисковому
  чтению; бинарный payload не разбирается как текст. Это устраняет обнаруженную
  при проверке перемешивание строк при одновременном вводе и paging.
  Обновлённый PC-мост выдаёт по одной команде только в ответ на `@ZBLK|POLL`
  от часов и завершает ответ `@ZBLK|IDLE`. Во время блочных запросов команды
  не отправляются. Старые прошивки остаются на прежнем асинхронном режиме.
- `./adb shell memory` и беспроводной `adb shell dumpsys meminfo` показывают
  занятое/свободное heap, отдельно internal/PSRAM и активный размер ZPager.

ZPager остаётся управляемым хранилищем сериализуемого состояния, а не
прозрачным Linux swap: его размер не добавляется к адресуемой RAM ESP32.
Изменений разметки, автоматического увеличения swap или очистки данных нет.

Проверены 100 Rust host-тестов (включая края секторных записей, покрытие damage,
совместное владение обоями, кэш курсоров и фрейминг), 4 теста стекового бюджета,
4 теста каталога, 3 теста PC input и 5 тестов журнала/моста. Release ESP32-S3 и упаковка проходят. Прошивка обновлена на подключённой
плате; проверка выполняется на копии PC-образа с Wi-Fi и BLE.
Аппаратный цикл: 40 переходов циферблат ↔ быстрые настройки с ADB-запросами
за 10,83 секунды, без таймаутов, panic и ошибок paging. После прогрева heap
стабилен на 1007000 байтах в этом сценарии (свободно 1221220, из них PSRAM
1201964 и internal 19256 байт). Это результат данного конечного теста, а не
обещание отсутствия утечек во всех приложениях. PC-сервер оставлен работающим
на тестовой копии образа; исходный образ не менялся.

# 2026-11-03: исправление переполнения стека при запуске

после `system_server handoff succeeded`. Причина подтверждена по ELF: основной

служб запрещено объединение стековых кадров инлайнингом. Кадр диспетчера диска
теперь 1216 байт, основной стек 156220 байт. В упаковку включена проверка
[стекового бюджета](tools/check_main_stack.py) с запасом 32 КиБ для вложенных вызовов.

Исправленная прошивка записана и проверена на физической плате с копией образа:
Wi-Fi/DHCP, синхронизация SNTP, BLE advertising и encrypted HID state 3,

  [Управление и ограничения](../App/system/app/Files/README.md).

  На экран выводятся реальные состояния; вымышленных кругов секундомера,
  трёх будильников или обещания вибрации без аппаратной поддержки нет.
- ADB сохраняет слушающий TCP-сокет при активном соединении, поддерживает до
  четырёх потоков одного клиента и откладывает подтверждение SYNC до записи DATA.
  Явное новое соединение заменяет старый транспорт; это не многопользовательский ADB.
- Файлы через `/sdcard/имя` и `/sdcard/Documents/имя` загружаются потоково до 16 МиБ.
  Редактор — до 64 КиБ; каталог — 32 файла/папки, путь до 80 UTF-8 байт.
  Большие файлы требуют userdata не менее 72 МиБ с доступным резервом 64 МиБ.
  Старые маленькие документы остаются совместимы. После записи нового blob-каталога
  не откатывайтесь на старую прошивку, которая не знает этот формат.

Для журнала выделено **ровно 64 КиБ** raw userdata по смещению 1,5 МиБ.
Это 128 записей по сектору с CRC, а не обещание 64 КиБ полезного текста.
Записи перезаписываются кольцом, экспорт возвращает только целые записи по порядку.
Сохранение выполняется владельцем диска по одной записи за итерацию;
при отключении питания последние ещё не сброшенные RAM-записи могут потеряться.
Незнакомые ненулевые данные в резерве не форматируются автоматически.

```sh
adb logcat
adb pull /data/log/watch.log ./watch.log
# Второе имя того же виртуального журнала:
adb pull /sdcard/Logs/watch.log ./watch.log
```

Доступ к файлам закрывается PIN-блокировкой. Аргументы ADB-команд с возможными
паролями не журналируются. Panic сохраняет короткий отчёт в RTC-памяти до
программного перезапуска; это не энергонезависимая память при снятии питания.
Для адресов нужен ELF **той же сборки**, которая прошита:

```sh
python3 Bootloader/tools/decode_backtrace.py --elf Bootloader/out/flash-bundle/firmware.elf ./watch.log
```

Сборщик flash bundle сохраняет соответствующий ELF и его SHA-256 в манифесте.
Не расшифровывайте старый backtrace новым ELF: результат не будет достоверным.
Логи могут содержать личные данные — они исключены из Git.

Проверено на host: 81 Rust-тест, в том числе SYNC 5 МиБ, remount/незавершённая
запись, декодирование JPEG/PNG, кольцевой журнал/CRC/очистка, ожидание запуска,
launcher и отрисовка экранов; 7 тестов упаковки/сохранения образов и 11 тестов
инструментов загрузчика. Gateway проверяется отдельно с синтетическим OAuth.
Физическая проверка BLE-сопряжения, многопоточного ADB и задержек UI остаётся
нужной на устройстве. В рамках этих изменений часы автоматически не прошивались.

# 2026-11-03: аварийный перезапуск и вход в сервисные режимы

Выбор теперь выполняется в обеих сборках **до обращения к SD/PC-диску**:

- В первые **2,5 секунды** после появления стартового экрана поверните энкодер.
  Положительное направление PCNT открывает **Fastboot+**, отрицательное — **Recovery**.
  Это физическое направление A=GPIO11/B=GPIO12, без пользовательского реверса;
  при перестановке A/B стороны меняются. Экран показывает подсказку +/−.
- Удержание кнопки энкодера **GPIO13 не менее 10 секунд** перезапускает часы
  прямо во время удержания. Для этого выделен TIMG1: UI, Rhai и ожидание диска
  не участвуют в отсчёте. Отпускание сбрасывает таймер. Кнопка BOOT платы — другая.
- Короткое/обычное длинное нажатие сохраняет прежние действия. Кнопка, которой
  вошли в Fastboot, поглощается до отпускания и не активирует пункт Start.
- Нет SD, ошибка GPT/AVB, загрузки пакета или запуска runtime — переход в Fastboot+.
  Отсутствующий сервер PC-диска даёт такой же переход после тайм-аута транспорта
  (около 30 секунд). Бесконечные циклы ожидания после ошибки удалены.
- Recovery встроено в **внутреннюю flash**, поэтому для самого меню SD не нужна.
  «Обновление USB» передаёт USB тому же сервисному Fastboot+, без нового поиска диска.

## Обновление внутренней прошивки

Остановите PC block server / просмотрщик, чтобы освободить последовательный порт.
Войдите в Fastboot+ или выберите Recovery → «Обновление USB», затем из корня:

```sh
python3 Bootloader/fastboot_tool.py --port /dev/ttyACM0 getvar:all
python3 Bootloader/fastboot_tool.py --port /dev/ttyACM0 update Firmware/target/xtensa-esp32s3-none-elf/release/firmware
```

Клиент сначала проверяет сервисный режим, закрывает свой serial-дескриптор,
затем вызывает espflash с [таблицей внутренней flash](partitions.csv).
Это реальное обновление ELF прошивки через протокол Espressif, не совместимость
с Android-командой fastboot flash. Новый ELF собирается командой ./flash pc --build-only
или ./flash sd --build-only под используемый носитель.

## Разделы системного PC-образа

[partition_tool.py](tools/partition_tool.py) работает с остановленным **образом на ПК**:

```sh
python3 Bootloader/tools/partition_tool.py --image Firmware/out/app-architecture-build/aosp-wear-sd.img list
python3 Bootloader/tools/partition_tool.py --image Firmware/out/app-architecture-build/aosp-wear-sd.img flash boot_a Firmware/out/app-architecture-build/boot.img
```

Проверяются обе GPT, границы, допустимое имя, размер и SHA-256 после записи.
Блокировка образа общая с PC-сервером и сборщиком. Для записи разрешены только
boot/init_boot/vendor_boot/vbmeta слотов a/b и super. Пользовательские области
userdata/misc/swap защищены от этого обновления. Запись одного раздела не атомарна:
при обрыве повторите операцию; используйте согласованный комплект образов одной сборки.
Это не удалённая запись SD внутри часов: стандартные USB fastboot download/flash
и установка update.zip с карты пока отсутствуют.

## Граница восстановления

Ранние сервисные режимы и таймер сейчас являются нативной частью Firmware во
внутренней flash; загрузочная библиотека читает внешний системный носитель.
Они работают при повреждённом SD/PC-образе. При повреждении самого исполняемого
кода во внутренней flash используйте штатный **BOOT/RESET ESP32 и espflash**.
Таймерный сброс работает при доступных прерываниях, не является аппаратным
отключением питания и не гарантируется при полном зависании CPU/запрете IRQ.
Проверки: 73 Rust-теста, 11 тестов инструментов, 7 тестов сборщика; сборки PC и SD успешны.
На подключённых часах эти изменения не прошивались: проверка платы остаётся отдельной.

# Обновление часов: состояние и запуск

## 2026-11-03: документы, калькулятор, циферблаты и KDE-мост

Этот раздел описывает текущую версию; прежние количества приложений и
ограничения проводника в исторических разделах ниже заменены им.

### Проводник и редактор

В меню 18 приложений. «Файлы» теперь работает с пользовательскими документами:
папки, просмотр UTF-8-текста, создание файла/папки, переименование, копирование
дерева папок, вырезание/вставка и подтверждение удаления. Удаляются файлы и
пустые папки. Существующие файлы при вставке не перезаписываются молча.
Системные обои выбираются в настройках и остаются read-only в ADB.

«Текстовый редактор» использует то же хранилище: выбор строки → нажатие →
правка RU/EN-клавиатурой → подтверждение. В конце списка — добавление строки,
сохранение и возврат. NL на второй странице символов добавляет перенос.
Изменения не пишутся на каждый символ. Выход с несохранёнными изменениями
предлагает сохранить, отбросить или отменить выход; незавершённый ввод можно
продолжить после возвращения из Home. Корректно проверяются лимиты UTF-8.

Хранилище WFSv1 — собственный ограниченный формат, **не FAT/ext4**:
32 записи суммарно с папками, файл до 3072 байт, полный путь до 80 байт.
Два каталога по 4 КиБ и по две копии на файловый слот занимают 264 КиБ
от userdata+2 МиБ. Это не пересекается с обоями, снимком, маркером swap
на +4 МиБ и дополнительными страницами swap от +8 МиБ. Чужие/занятые области
не форматируются. Первое создание проверяет резерв на пустоту.

Перед публикацией нового каталога данные записываются в другую копию и
проверяются чтением; каталог имеет поколение и CRC. При оборванной записи
остаётся целая старая либо новая версия. Это проверено моделью обрыва по
секторам; поведение конкретной карты при отключении питания ещё не проверено.
CRC защищает от ошибок данных, а не от намеренного изменения носителя.

ADB SYNC поддерживает STAT/LIST/SEND/RECV в /sdcard/Documents: эти пути
соответствуют корню WFSv1. Создание папок выполняется на часах. Доступ к
документам прекращается при PIN-блокировке. Примеры:

```sh
adb push note.txt /sdcard/Documents/note.txt
adb pull /sdcard/Documents/note.txt ./note-copy.txt
```

Файлы сохраняются в userdata карты или PC-образа. Штатный сборщик сохраняет
весь существующий userdata; новый пустой полный образ нельзя записывать поверх
карты с нужными документами без резервной копии.

Модули: [file_store.rs](../Firmware/src/services/file_store.rs),
[apps/files.rs](../App/system/app/Files/main.rs), [pages_files.rs](../App/system/app/Files/view.rs).

### Калькулятор и пять циферблатов

Калькулятор: выражения со скобками и приоритетом ×/÷, проценты, квадрат,
квадратный корень, смена знака выражения, повторное «=», отдельная строка
выражения и иконка backspace. Проценты при +/− относительны к левой сумме:
200+10%=220; при умножении 200×10%=20. Результат до 8 дробных знаков;
есть ограничение величины и длины выражения, проверка деления на ноль,
отрицательного корня и глубины скобок. Это не символьная/CAS-система.

Аналоговый циферблат получил минутную шкалу, отметки 12/3/6/9 и дату ниже
строки состояния. Добавлены «Минимализм» с секундами и «Панель» с погодой,
будильником и таймером. Панель показывает последний реальный прогноз;

### KDE Connect

Прямой KDE Connect LAN-клиент с TLS/сертификатами на ESP32 не реализован.
Проверен [официальный LAN backend KDE](https://github.com/KDE/kdeconnect-kde/blob/master/core/backends/lan/lanlinkprovider.cpp)
и [описание пакетов проекта KDE](https://github.com/KDE/kdeconnect-meta/blob/work/protocol-schemas/protocol.md).
Они требуют отдельного протокола и сопряжения; BLE HID/Pixel Watch не дают
автоматической совместимости.

Добавлен [kde_bridge.mjs](tools/kde_bridge.mjs): Node.js + установленный
kdeconnect-cli на Linux, существующий локальный PC-сокет часов или обычный ADB.
Телефон заранее сопрягается с компьютером штатным KDE Connect.

```sh
node Bootloader/tools/kde_bridge.mjs --list
node Bootloader/tools/kde_bridge.mjs --device ID_ИЗ_СПИСКА
# Для SD/Wi-Fi ADB: сначала adb connect IP:5555, затем
node Bootloader/tools/kde_bridge.mjs --device ID_ИЗ_СПИСКА --watch IP:5555
```

Открыть «Телефон», сверить код из 4 символов и разрешить мост на часах.
Команды возникают только по нажатию пользователя; у неподтверждённого моста
и при PIN-блокировке доступа нет. Принятый запрос потребляется до обращения
к KDE, чтобы после переподключения не продублировать звонок/отправку;
авария процесса в этот момент может потерять команду, её нужно повторить.
При перезапуске моста сначала отключить старый мост в часах.

KDE обеспечивает своё защищённое соединение с телефоном; ADB-участок этим
не шифруется. Для стенда предпочтителен локальный PC-сокет, для TCP ADB нужна
доверенная сеть. На данном компьютере kdeconnect-cli установлен, доступных
сопряжённых устройств найдено 0. Мост прошёл автономные тесты без отправки
сообщений реальным устройствам; физический обмен с телефоном ещё нужен.

  значения. Длинные подписи помещаются в отведённую ширину с переносом или
  многоточием по границе UTF-8.
- У общей клавиатуры RU/EN один нижний ряд: регистр, буквы/символы, язык,
  удаление последнего символа, отмена, пробел и подтверждение. Удаление,
  регистр, язык, пробел и подтверждение обозначены иконками. Стрелка вверх
  меняет регистр букв; на страницах символов её место занимает «1/2» или «2/2».
  Кнопки изменения размера текста в клавиатуре нет.
- Над буквами до трёх подсказок из небольшого локального словаря городов,
  имён и обычных слов. Колесо выбирает подсказку, нажатие заменяет последнее

  Это начальное словарное дополнение, без обучения, автокоррекции и свайп-ввода.
  Жесты с будущим акселерометром пока не реализованы.

## Запуск, читаемый интерфейс, погода на самих часах; веб-доступ удалён

### Запуск

После восстановления настроек остаётся экран запуска с «Запуск…» и текущим
этапом: графика, Bluetooth или интерфейс. Минимальная длительность — 2 секунды,
завершение учитывает очередь чтения обоев и старт Bluetooth. Верхняя граница
8 секунд не даёт неисправному дополнительному сервису навсегда заблокировать
интерфейс. Подключение к точке доступа/DHCP/NTP могут продолжаться в фоне:
отсутствие интернета не считается причиной не запускать часы. Это не обещание
готовности всех внешних сервисов к моменту исчезновения сообщения.

Нет блокирующего delay для заставки: продолжается основной цикл, операции
накопителя и радио. Обычный ввод удерживается до завершения заставки, меню
питания доступно. Выбранный системный PNG запрашивается заранее. Аварийные
экраны по-прежнему не требуют системного пакета ресурсов.

### Значки, текст и приложения

- Цветные круглые подложки и тёмные Material Symbols по присланным примерам;
  при выборе затемняется подложка, без скачков размеров.
- Добавлены официальные значки partly_cloudy_day, public, air и memory из
  того же закреплённого Google Material Symbols. Системный атлас содержит
  35 значков. Новый загрузчик также принимает прежний пакет из 31 значка;
  для отсутствующих новых значков использует подходящую старую пиктограмму.
- Roboto пересобран с настоящими размерами 14 px (было 11), 18 px (было 16)
  и отдельным сглаженным атласом 36 px для крупных надписей. Цифры циферблата
  остаются Roboto Light 64 px. Все 166 UI-глифов включают кириллицу и знаки
  градусов, многоточия и тире. Крупный текст 36 px больше не получается простым
  удвоением пикселей маленького глифа.
- Скорректированы вертикальное положение текста, переносы и интервалы.
  Длинные строки обрезаются по границам UTF-8 с многоточием; raw-поля имени
  и города не переводятся через словарь системных меток.
- «Об устройстве» — прокручиваемые строки с системой, реальной моделью платы,
  именем и версией, без декоративной буквы A. В настройках swap две крупные
  карточки на экран. Остальные меню используют обновлённые общие компоненты.
- В меню 15 приложений: новые «Погода», «Мировое время», «Дыхание».
  Мировое время использует реальные часы устройства и вручную выбранное
  смещение UTC -12…+14; базы DST/автоматического перехода на летнее время нет.
  Дыхание — двухминутный визуальный ритм 4 секунды вдох / 6 секунд выдох;
  экран остаётся включён до конца сеанса и ещё 5 секунд. Выход останавливает
  сеанс; приложение не выдаёт показаний медицинских датчиков.

### Погода без компьютера и телефона

Часы сами обращаются к API через подключённый Wi-Fi. Никакой помощник на ПК,
ADB-мост погоды или парсинг HTML для получения прогноза не требуются.

- «Город» открывает общую RU/EN клавиатуру; нажатие «Поиск» отправляет запрос
  [геокодеру Open-Meteo](https://open-meteo.com/en/docs/geocoding-api). Сейчас
  выбирается первое совпадение; имя найденного города показывается на экране.
- «Рядом» получает приблизительные координаты внешнего IP сети часов через
  [IP-API](https://ip-api.com/docs/api:json). Это не GPS: точность зависит от
  оператора, точки доступа и VPN, в интерфейсе есть пометка «приблизительно».
- Затем [Open-Meteo](https://open-meteo.com/en/docs) возвращает температуру,
  ощущаемую температуру, влажность, ветер и код погоды. «Обнов.» запрашивает
  прогноз для последнего выбранного места; для новой IP-геопозиции — «Рядом».
- Место сохраняется в базовом слоте 74 (WLOC) только при смене успешно
  загруженного местоположения. После перезапуска можно нажать «Обнов.»;
  погодные показания не выдаются за текущие из старого дискового кэша.
- Прогноз хранится в RAM. Есть состояния без Wi-Fi, поиска, отсутствия города,
  DNS/соединения, таймаута и некорректного ответа. Старый успешный прогноз
  остаётся виден при ошибке обновления; данные старше часа помечаются.

Клиент неблокирующий, отдельные DNS/TCP сокеты, DNS из DHCP с резервными
публичными серверами. Буферы в PSRAM, ответ ограничен 12 КиБ, приём — максимум
2048 байт за проход цикла, HTTP chunked поддерживается. Таймаут одного этапа
20 секунд; нет бесконечного retry или фонового опроса сервиса. Запросы идут
только по действию пользователя, не чаще раза в 3 секунды. Каждый этап —
обычный HTTP к фиксированным публичным API; TLS/HTTPS в этом клиенте пока нет.
Ключи, пароли, логины и другие защищённые операции через него не передаются.

Модули: [src/weather.rs](src/weather.rs) — состояние/редактор/выбор места;
[src/net/weather_client.rs](../Firmware/src/services/net/weather_client.rs) — DNS/HTTP/JSON;
[src/material/pages_weather.rs](../App/system/app/Weather/weather.rs) — экран погоды
и две новые утилиты; [src/startup.rs](../Firmware/src/startup.rs) — политика запуска.

## Выбор объёма ZPager: 32–512 МиБ в самой прошивке

Открыть «Настройки → Система → Память и swap» или одноимённое приложение.
Доступны суммарные размеры 32 / 64 / 128 / 256 / 512 МиБ. Колесо выбирает
вариант, нажатие сохраняет. Экран отдельно показывает активный и выбранный
размер. Новое значение применяется при следующем запуске; автоматической
перезагрузки нет. Неподходящий размер отклоняется, ошибка записи показывается
на экране. По умолчанию остаются прежние 32 МиБ.

Физический раздел swap не перемещается и не увеличивается на часах. Первые
32 МиБ остаются в нём: Activity-страницы и постоянные слоты настроек, PIN,
Wi-Fi и BLE сохраняют свои адреса. Новые номера страниц отображаются на
зарезервированную raw-область userdata. Для 512 МиБ это 32 + 480 МиБ.
PageStore работает с объединённым диапазоном и u32-номерами страниц,
максимальный общий диапазон — 131 071 слот по 4096 байт (4080 байт payload).
Это доступная ёмкость хранилища записей, не текущий объём занятых страниц.

Условия:

- Нужен штатный базовый swap 32 МиБ и поддерживаемый сырой формат userdata.
  Известные файловые системы/чужая разметка служебной области отклоняются.
  Утилита не ищет свободные блоки внутри FAT/ext4 и не создаёт файл swap там.
- Резервируется диапазон от 8 МиБ внутри userdata; прежние обои и снимок
  экрана в начале раздела не затрагиваются. Сохраняется минимум 16 МиБ
  пространства вне этого диапазона. Размер проверяется перед записью.
- В стандартном образе с userdata 265 МиБ доступно до 256 МиБ ZPager.
  Для 512 МиБ нужно сначала расширить userdata на карту (разделом не менее
  504 МиБ); расширенная карта 8 ГБ это позволяет.
- На смещении 4 МиБ внутри userdata находится маркер SWEXv1 с началом,
  максимальным зарезервированным размером и CRC. Конфигурация версии 1
  хранится в базовом слоте 73 с тегом SWPC. Формат прежних страниц не менялся.
- Маркер записывается/читается обратно до сохранения настройки. При сбое
  маркера/конфига расширение не подключается; базовые страницы остаются
  отдельными. Записи не объявляются атомарными при потере питания.
- Уменьшение лимита не очищает прежние страницы и не снимает максимальный
  резерв userdata: его нельзя считать свободным для будущей файловой системы.
  Возможность возвращать этот резерв потребует отдельного механизма.

Это не Linux swap и не расширение физической RAM. ZPager явно сохраняет
сериализуемые состояния/кэши через PageStore. Сейчас Activity использует
прежние низкие номера страниц; увеличение доступного диапазона само по себе
не заставляет Rhai, сетевые буферы или произвольные объекты выгружаться на SD
и не гарантирует ускорения. Механизм распределения общего heap в swap здесь
не реализован. Полезная ёмкость меньше выбранного числа МиБ из-за заголовков.

Проверить состояние через обычный ADB:

```sh
adb shell dumpsys swap
```

Поля active/selected/maximum — суммарная ёмкость backing, не RAM. В логах
ZPager пишет результат явного сохранения. Фоновый цикл не сканирует карту:
возможности определяются при старте, I/O настройки выполняется только по
нажатию через единственного владельца диска.

Модули: [src/swap_config.rs](../Firmware/src/services/swap_config.rs) — формат/проверки/настройка;
[src/page_store.rs](../Firmware/src/services/page_store.rs) — отображение дополнительных страниц;
[src/material/pages_apps.rs](../Firmware/src/material/pages_apps.rs) — экран выбора.
Собраны PC и SD release без предупреждений. Тесты, прошивка и изменение
носителя не запускались по просьбе владельца. На устройстве сохранение,
перезапуск и доступ к расширенным страницам пока не проверены.

## Вертикальная сетка и расширение userdata до конца карты

Сетка приложений больше не заменяет горизонтальные страницы по шесть иконок.
Остаются три колонки, но окно смещается вниз по одному ряду при переходе
фокуса к нижним приложениям. Верхний ряд уходит, следующий появляется снизу;
горизонтальные точки страниц заменены обычным вертикальным индикатором.
Свайпы вверх/вниз в сетке перемещают фокус на ряд (в списке — на один пункт).
Управление колесом и сохранение выбранного вида меню остаются доступны.

Добавлена утилита [grow_userdata.py](../Firmware/tools/grow_userdata.py):

- По умолчанию открывает носитель только для чтения и показывает план.
- Проверяет обе GPT, CRC заголовков и таблиц, ожидаемые 13 разделов часов,
  отсутствие перекрытий, границы userdata и отсутствие смонтированных разделов
  или активного swap на выбранной карте. При несоответствии отказывается.
- С --apply сохраняет затрагиваемые сектора GPT/MBR в JSON до записи,
  расширяет только конец последнего userdata и переносит резервную GPT к концу
  носителя. Начала, GUID, система, swap и прежнее содержимое разделов не меняются.
- Сначала записывает резервную GPT, затем основную, обновляет CRC/защитный MBR,
  синхронизирует запись и сравнивает записанные сектора с ожидаемыми.
- При повторном запуске на уже расширенной карте ничего не записывает.

На момент подготовки изменений видна карта /dev/sda размером 8 018 460 672 байт,
userdata — 265 МиБ. После расширения он займёт примерно 7,23 ГиБ, а super
останется 128 МиБ и swap — 32 МиБ. Это размер раздела, не свободное место
файловой системы: сейчас userdata содержит служебные сырые области, полноценная
пользовательская ФС ещё не добавлена. Небольшой установочный образ остаётся 512 МиБ.

Запуск из корня проекта, **если карта по-прежнему /dev/sda** (проверить lsblk):

```sh
# Показать план без записи:
sudo python3 Firmware/tools/grow_userdata.py --device /dev/sda
# Применить с резервной копией метаданных на компьютере:
sudo python3 Firmware/tools/grow_userdata.py --device /dev/sda --apply --backup-dir Bootloader/out/gpt-backups
```

Не записывать полный 512-МиБ образ повторно после расширения: это вернёт старую
разметку и может перезаписать пользовательские данные. Для текущего изменения
меню достаточно обновить загрузчик; файл grow_userdata.py работает с уже
записанной картой отдельно и не требует перезаписи системы.

Реальная карта не изменена: доступ /dev/sda закрыт для текущего пользователя,
sudo требует пароль. Команду --apply владелец запускает вручную. Собраны PC/SD
профили без предупреждений, проверен синтаксис Python. Тесты и прошивка часов
не запускались по просьбе пользователя; запись/восстановление GPT не проверялись
на устройстве. Резервная копия GPT сохраняет метаданные, не является копией
содержимого всех разделов и не делает запись атомарной при потере питания.

## Актуально: иконки и обои перенесены в системный образ

Исправлено разделение ресурсов: исходные SVG, оба атласа и их сборщик теперь
находятся в Firmware/resources/material-symbols и Firmware/tools. PNG остаются
в Firmware/walp; порядок задаёт manifest.json. В исполняемый образ ESP32 больше
не включаются include_bytes с PNG/атласами. Шрифт и самостоятельная отрисовка
запуска/recovery/fastboot остаются в загрузчике.

Сборщик Firmware упаковывает ресурсы в system/usr/share/aosp-wear/ui-resources.bin
внутри super.img, одинаково для system_a и system_b. Загружается активный слот.
Проверяются версия пакета, границы, размеры атласов и CRC каждого читаемого
ресурса. Ресурсы не входят в ограниченный 32-КиБ Rhai bundle.

Буферы ресурсов выделяются в PSRAM, чтобы не занимать внутренний heap
радиодрайверов. В RAM постоянно находятся только два атласа (22 878 байт), а PNG загружается
по запросу через владельца диска и кэшируется один. ADB удерживает ссылку на
передаваемый PNG до завершения отправки; картинки не получают фиктивный
static lifetime. Данные Vec не копируются при передаче владения в Arc.
Новая ревизия ресурса обновляет экран, даже когда состояние меню не менялось.
Текущий фон после декодирования по-прежнему хранится в RAM как RGB565.

Старый системный образ не содержит пакета: загрузчик выдаст понятный лог
Resources: system image needs UI resource update. Обычные иконки/стандартные
обои без пакета недоступны; boot/recovery/fastboot не зависят от него.
Нужны **и новый загрузчик, и новый super.img**, поэтому инструкция ниже из
предыдущего обновления про loader-only к этой миграции не относится.

Обновление:

- Для PC: из Bootloader выполнить ./flash pc без AOSP_WEAR_SKIP_FIRMWARE_BUILD.
  Скрипт соберёт системный образ и ESP32. При сборке существующего PC-образа
  сохраняются metadata, swap с настройками и userdata.
- Для SD: обновить системный образ на карте, затем прошить ESP32 через

  записью сохранить нужные данные. Обновление только super позволяет сохранить
  текущие пользовательские разделы, но требует правильного смещения из GPT.
- В этом обновлении физическая карта/ESP32 не записывались. Новый образ PC
  собран в Firmware/out/target/product/zero. Тесты не запускались по просьбе
  пользователя; собраны профили PC и SD. Работу на устройстве проверяет владелец.

Размер PC-приложения после переноса — около 1,49 МБ (36% раздела) вместо

## 2 ноября: приложения, диагностика и нагрузка интерфейса

- Иконки приложений увеличены с 24 до 30 px, круги сетки — с 26 до 29 px.
  Используются официальные Material Symbols Rounded; отдельный большой атлас
  содержит сглаженные маски, без масштабирования пикселей в каждом кадре.
- В меню 11 приложений: к прежним шести добавлены «Калькулятор», «Файлы»,
  «Передача файлов», «Диагностика» и прямой вход в фонарик. Сетка листается
  страницами по шесть; список и сетка используют один реестр.
- Калькулятор: четыре операции, десятичные числа, проценты как деление на 100,
  смена знака, удаление и сброс. Результат округляется до четырёх знаков после
  запятой; деление на ноль и выход за диапазон показывают ошибку. Колесо
  перемещает фокус, нажатие вводит символ, удержание возвращает назад.
- «Файлы» пока просматривает встроенные обои, позволяет выбрать их для
  циферблата. Произвольного файлового менеджера FAT/ext4 здесь нет: userdata
  использует служебные сырые области. Размеры носителя, super и userdata
  доступны в диагностике. Не показываем выдуманные каталоги Android.
- «Передача файлов» показывает текущий адрес ADB и инструкции. Это передача
  по Wi-Fi через ADB, совместимости с протоколом Android Quick Share нет.
  ADB должен быть включён, компьютер и часы — в одной сети.

Примеры для обычного системного ADB:

```sh
adb connect IP_ЧАСОВ:5555
adb push picture_240x280.png /sdcard/Wallpapers/current.png
adb pull /sdcard/Wallpapers/1.png ./watch-wallpaper.png
adb shell dumpsys meminfo
adb shell dumpsys hardware
```

Встроенные PNG доступны под именами 1.png…16.png только для чтения.
SYNC поддерживает STAT/LIST/RECV для этой виртуальной папки. PNG читается
прямо из flash порциями по 512 байт с ожиданием ADB ACK; вся картинка в RAM
не копируется. Встроенные имена защищены от SEND. Загрузка current.png
сохраняет преобразованные RGB565 в userdata и выбирает пользовательские
обои; исходное имя/PNG после этого не хранится и не выдаётся через RECV.
Это ограниченный сервис обоев, не общий доступ ко всему диску.

Диагностика открывается из приложений или «Настройки → Система → Диагностика»:

- Время работы, частота CPU и характеристики платы.
- Текущий общий свободный heap и свободная внутренняя память; предупреждение
  при менее 16 КиБ внутреннего heap, без автоматического отключения служб.
- Ёмкость носителя и размеры разделов. Они читаются через владельца диска
  только при первом открытии диагностики, затем используются из кэша.
- Длительность последнего нарисованного кадра, последнего вызова Rhai render,
  число попаданий в кэш сцены, текущие Wi-Fi/BLE состояния. Это не замер FPS
  и не процент загрузки CPU. Данные кадра могут относиться к прошлой странице.
- Температура пока отмечена как недоступная: в esp-hal 1.0 нет готового
  драйвера S3 TSENS; встроенный датчик есть в самом чипе. Для его поддержки
  нужен отдельный порт драйвера и проверка на устройстве. Ток и заряд также
  не измеряются: соответствующей схемы измерения сейчас нет.

В «Настройки → Экран» добавлены яркость обоев 40/60/75/85/100% и отключение
секундной стрелки аналогового циферблата. Без секундной стрелки часовая и
минутная обновляются по минутам. Настройки v4 по-прежнему занимают 12 байт;
восстановление настроек v1/v2/v3 сохранено. В «Системе» доступно меню питания.

### Производительность и структура

- Секунды скрытого таймера/секундомера и скрытый прогресс медиаплеера больше
  не делают статические страницы невалидными. Таймеры продолжают идти,
  оповещения используют отдельное поле и сохраняют обновления.
- Полностью непрозрачные пиксели иконок записываются напрямую, без смешивания.
- Новые утилиты не создают фоновых задач; арифметика выполняется по нажатию,
  живые значения heap читаются только при открытой диагностике.

  [src/apps/calculator.rs](../App/system/app/Calculator/main.rs) — арифметика;
  [src/apps/storage.rs](../Firmware/src/services/storage_info.rs) — кэш сведений диска;
  [src/material/pages_apps.rs](../Firmware/src/material/pages_apps.rs) — отрисовка.
- Нативные страницы используют overlay, не расширяют пятибитный screen ABI
  старого Rhai на карте. Блокировка закрывает overlay, питание остаётся

  overlay-страницы полностью; основной целевой интерфейс — физический ST7789.

Собраны release-профили PC и SD, без предупреждений. Тесты, прошивка и
проверка на часах не запускались по просьбе пользователя. Ускорение и
устойчивость под нагрузкой требуют проверки на реальном устройстве.
Перезаписывать образ SD для этих изменений не требуется: меняется загрузчик.
Из каталога Bootloader можно использовать:


### Сколько энергии потребляют часы

Программного измерения тока сейчас нет. По [даташиту ESP32-S3 v2.2,
таблицам 5-8/5-9](https://documentation.espressif.com/esp32_s3_datasheet_en.pdf)
при 240 МГц и выключенном RF потребление чипа в приведённых сценариях
составляет примерно 33–108 мА (различаются инструкции, число активных ядер
и включённые такты периферии). Для BLE RX приведено 93 мА, для BLE TX
21 dBm — 335 мА; это условия измерений чипа, а не средний ток наших часов.
На плате добавляются экран/подсветка, SD, память, светодиоды и преобразователь
питания. Числа даташита нельзя выдавать за измеренный расход всей сборки.

Для измерения по USB нужен USB-тестер с поддержкой используемого data-подключения;
для аккумулятора — измерение тока на стороне аккумулятора. Сравнить средний
ток хотя бы за минуту в режимах: экран включён, AOD, экран выключен; затем
повторить с выключенными Wi-Fi/BLE. Погашенный экран не означает deep sleep
CPU, а LCD AOD сохраняет подсветку. Яркость обоев/программное затемнение
меняют RGB-пиксели и сами по себе не гарантируют снижения тока подсветки.
Автономность оценивается как ёмкость аккумулятора в мА·ч / средний ток
на стороне аккумулятора в мА, с учётом потерь и доступной ёмкости.

## Жесты колёсиком и общая клавиатура

- В рабочем интерфейсе зажатая кнопка + вращение вперёд отправляет свайп
  вправо, вращение назад — влево. Учитывается настройка обратного направления
  энкодера. Повтор в одном направлении ограничен интервалом 180 мс.
- Нажатие, участвовавшее в жесте, поглощается целиком: отпускание не открывает
  строку, не вызывает Back/Home и не открывает питание. Удержание без вращения
  сохраняет прежние действия. Fastboot/Recovery используют обычное управление.
- `text_input.rs` содержит общую модель клавиатуры, `material/keyboard.rs` —
  одну отрисовку для имени устройства и Wi-Fi. Строки QWERTY/ЙЦУКЕН,
  RU/EN, Shift, две страницы символов, пробел, удаление, ввод и отмена.
- Фокус идёт по буквам, затем по служебным клавишам в порядке расположения.
  Клавиши сохраняют размер; выбранный фон темнее. Имя сохраняется через OK,
  пароль передаётся подключению Wi-Fi через «Ввод». Ограничения: имя 32,
  пароль 64 UTF-8 байта; выход за лимит показывается в заголовке.
- При отображении конца пароля соблюдаются границы UTF-8. Пароль по-прежнему
  не добавляется в desktop/web-сериализацию. Голосового ввода пока нет.

Сборка проверяется без запуска тестов и без прошивки устройства по просьбе
пользователя. Для обновления с текущим системным образом достаточно:

```sh

```

Для загрузки с карты заменить `pc` на `sd`.

## Исправление повторной паники BLE/RTOS

Лог PC-сборки от 2 ноября 11:57 UTC сопоставлен с её локальным ELF
(построен в 14:57:03 +0300). PC `0x421bf7bb` находится в
`esp_rtos_queue_receive`; следующие кадры — `btdm_controller_task` и
`task_wrapper`. До сбоя успешно загружены система, Wi-Fi и BLE; последняя
строка интерфейса не доказывает, что ошибка произошла в отрисовке.

В используемой esp-rtos 0.2.0 найден отсутствующий upstream-fix для Xtensa:
начальные PS задач не содержат EXCM/UM, а idle-контекст наследует PS
запускающей задачи. Разработчики исправили гонку прерывания при восстановлении
контекста в [#4580](https://github.com/esp-rs/esp-hal/pull/4580) и
[#4591](https://github.com/esp-rs/esp-hal/pull/4591).

Через `[patch.crates-io]` подключена локальная копия esp-rtos 0.2.0 в
`vendor/esp-rtos`. Из исходников изменён только `src/task/xtensa.rs`:
PS новой задачи — `0x50030`, idle — `0x40030`. Сохранены версии HAL,
радиодрайвера и все функции часов. Полное описание происхождения патча
находится в `vendor/esp-rtos/BACKPORT.md`; лицензии upstream сохранены.
Cargo registry пользователя не редактировался.

Это устранение конкретного известного дефекта зависимости, согласующегося
с трассировкой. Подтвердить отсутствие паники на часах ещё должен пользователь:
тесты, запуск на устройстве и прошивка здесь не выполнялись.

```sh
AOSP_WEAR_SKIP_FIRMWARE_BUILD=1 ./flash pc
```

Для SD используется та же команда с `sd`; образ карты менять не требуется.

## Текущее обновление: обычный ADB, обои и режимы экрана

Дальнейшие тесты и прошивка не запускались по просьбе пользователя.
Выполнена только проверка компиляции и сборка; поведение проверяет владелец.

- Реальная TCP ADB-служба существовала до локального адаптера. Теперь в ней
  выделен `net/adb_transport.rs`, добавлен потоковый `adb logcat`, включая
  команду клиента `export ANDROID_LOG_TAGS=''; exec logcat`. Поддержаны
  `-d`, `-c`, `-t/-T N`, уровни/теги и основные форматы. Буфер на часах —
  32 ограниченные записи в RAM; reboot его очищает. ROM/внешний panic-вывод
  не перехватывается автоматически, для него нужен serial.
- Ввод ADB больше не копирует 1024-байтный пакет через цепочку функций.
  Буфер ответа вынесен из стека, ответы идут по 512 байт с подтверждениями,
  приём сети ограничен одной порцией за итерацию. Это снижает давление на
  стек, но устранение присланной `LoadProhibited` не подтверждено. По адресам
  без точного соответствующего ELF нельзя объявлять первопричину найденной.
- Общие идентификаторы вынесены из adb.rs в `device_info.rs`, подключённый
  из main.rs. `PRODUCT_NAME=aosp`, `PRODUCT_DEVICE=aosp`, бренд AOSP.
  Имя владельца отдельно: **Система → Имя устройства**, редактор колёсиком,
  сохранение в swap slot 72. Доступно и через `settings put global device_name`.
- Имя используется в свойствах/настройках и BLE-рекламе; активная связь и
  телефонный кэш могут сохранять старое имя до переподключения. GAP-имя
  создаётся при запуске BLE-службы.
- `adb push image.png /sdcard/Wallpapers/current.png` принимает PNG 240×280,
  8 бит, без interlace, до 320 КиБ. SYNC приёмник — `adb/sync.rs`, декодер и
  встроенный каталог — `wallpapers/`. Отдельный владелец диска сохраняет
  данные до успешного SYNC ACK. Это ограниченная загрузка обоев, не общий
  файловый сервер. При занятом/несовместимом userdata возвращается ошибка.
- Включены 16 исходных PNG из Firmware/walp. Выбор — **Экран → Выбор обоев**.
  Свои обои сохраняются в userdata; стандартные находятся в коде загрузчика.
  Затемнение фоновой картинки уменьшено: 85% вместо прежних 40%.
- За 10 секунд до таймаута яркость меняется сразу на 15%, без анимации.
  При AOD, выключенном по умолчанию, после таймаута панель выключается.
  Включённый AOD показывает только тёмные часы с обновлением раз в минуту
  и небольшим смещением; первое действие только пробуждает. PIN-политика
  сохранена. LCD-подсветка остаётся включённой, экономия OLED не обещается.
- Вид списка/сетки сохраняется в настройках v3. Поддерживается чтение старых
  настроек v1/v2. Геометрия основных строк, кнопок, сетки и таймера при фокусе
  не меняется, выбранный фон становится темнее.

Загрузка после обновления (перезаписывать карту не требуется):

```sh
AOSP_WEAR_SKIP_FIRMWARE_BUILD=1 ./flash sd
adb connect <IP-часов>:5555
adb logcat
```

## Оптимизация фонового цикла и logcat

- В профиле с радио основной цикл спит через `CurrentThreadHandle::delay`,
  вместо активного ожидания 20 мс. В профиле без RTOS остаётся HAL-задержка.
- Скриптовая Material-сцена кэшируется по состоянию. Время, таймер,
  секундомер, будильник и PIN-политика обновляются нативно при каждом тике;
  legacy-текстовые скрипты не кэшируются.
- Фоновые проверки интерфейса идут раз в секунду, во время короткого
  затемнения — чаще, с сохранением точных dim/off-дедлайнов.
- SD- и PC-транспорт передают M3 только подписавшемуся просмотрщику,
  без дубликатов. Подписка истекает через 15 секунд без SYNC/PING.
- `shell display` дополнен счётчиками VM и раздельным временем растеризации,
  композиции и SPI. До изменения на часах замерено около 185 мс на кадр;
  процент улучшения после изменений пока не подтверждён на устройстве.

Добавлен `./adb logcat`: живые USB-логи либо подключение к PC-мосту,
фильтры `Tag:D` / `*:W`, форматы `threadtime`, `time`, `brief`, `raw`.
Сервер ПК хранит 128 записей для `-d`, `-t N`, `-c`; прямой USB-режим
истории не имеет. `@ZWUI` исключён из обычных логов. Метки времени — время
получения на ПК, PID/TID равны нулю, уровни старых строк без префикса
определяются по содержимому. Это ZADB-адаптер проекта, а не Android adbd.
Переходы экранов пишутся с тегом `ActivityTaskManager` и uptime устройства.

## Текущая задача: новая система на карте 8 ГБ

Цель — запуск новой системы с подключённой карты 8 ГБ. Исследование старой
карты не является обязательным шагом этой задачи. ПК сейчас сообщает для
целевой карты 8 018 460 672 байта / 15 661 056 секторов по 512 байт и GPT
с нужными 13 разделами.

Добавлен сквозной host-тест tools/runtime-check/src/image_boot.rs. Он открывает

GPT → выбор слота → Android boot/AVB → super/liblp → CPIO → Rhai Runtime.
Запуск Material-интерфейса и подтверждение успешной A/B-загрузки проходят;
записи метаданных при тесте хранятся в RAM и не меняют исходный образ.

```sh

```

Тест запускается явно после сборки Firmware: generated image не входит в Git,
поэтому обычные unit-тесты чистого checkout не требуют его наличия.
Для следующей проверки на часах используется обычный исходный SD-стек:

```sh

```

Перед прошивкой карта 8 ГБ с новым образом должна находиться в часах,
предыдущий монитор espflash закрыт. В логе ожидается original ExclusiveDevice
и startup=original embedded-sdmmc 0.10, а не gpio-mode0 / checked startup v3.
Повторная запись образа для смены драйвера не нужна. Успех загрузки на самом
устройстве должен быть подтверждён фактическим SYSTEM SERVER / handoff.


## Актуальный SD-режим после сравнения с исходниками

Обычный запуск снова использует исходный путь из Git до восстановления UI:
SPI2 mode 0, 400 кГц → 10 МГц после инициализации, ExclusiveDevice и
SdCard::new(...).num_bytes() из embedded-sdmmc 0.10 с CRC. Изменения интерфейса
сохраняются. Командная инициализация из sd_init.rs теперь только по явному
AOSP_WEAR_SD_CHECKED_STARTUP=1; программный SPI — отдельная опция
AOSP_WEAR_SD_SOFTWARE_SPI=1. Разделы ниже про startup v2/v3 описывают историю
диагностики и её дополнительные режимы, а не обычный путь загрузки.

В логе обычного режима должны быть transport=original ExclusiveDevice и
startup=original embedded-sdmmc 0.10 / CRC on. Его восстановление ещё не означает
подтверждённое устранение сбоя на физической карте.

На второй карте получены успешные ACMD41/CMD58 и чтение ёмкости, затем
GPT BadSignature. Это не ошибка инициализации SD. Пользователь указал, что
подключённая к ПК карта со старой системой; ядро ПК видит на ней GPT и 13
разделов. Без сравнения прочитанных секторов считать её FAT/несовместимой нельзя.
Сектор устройства на ПК — 512 байт. Есть и расхождение ёмкостей в сообщениях:
7791 МиБ в логе часов и 116,5 ГиБ у подключённого кардридера. Соответствие
конкретной физической карты этим сообщениям и причины расхождения ещё проверяются.

При ошибке GPT новый disk_probe.rs читает LBA0 и дважды LBA1, выводит первые
16 байт, сигнатуру MBR и типы разделов, сравнивает оба полных чтения сектора 1.
Никаких записей этот код не выполняет; это проверено отдельным host-тестом.
Для доступа к первым 34 секторам карты на ПК нужны права чтения устройства:

```sh
sudo dd if=/dev/sda bs=512 count=34 status=none > /home/denis/Developer/Android-For-ESP32S3/Bootloader/out/card-header.bin
```

Эта команда читает заголовки в локальный файл. /dev/sda допустим только пока
lsblk показывает именно подключённый кардридер; это не команда прошивки карты.


Это Rust/Rhai-система для ESP32-S3 N4R2, экран ST7789V3 240×280.
Она использует оформление по предоставленным фотографиям, но не запускает
Android/Wear OS, APK или сервисы Google. Язык по умолчанию — русский.

## Сборка и microSD

Остановите сервер PC block (Ctrl+C в его терминале), если он обслуживает образ,
который собираетесь пересобрать. Сборщик сохраняет пользовательские разделы
совместимого образа и отказывается менять занятый образ или его размер.

Из корня проекта:

```sh
cd /home/denis/Developer/Android-For-ESP32S3
./flash sd --build-only
lsblk -o NAME,SIZE,MODEL,MOUNTPOINTS
```

Выберите **всю карту**, например `/dev/sdX`, и размонтируйте её смонтированные
разделы. Следующая команда полностью заменяет содержимое выбранного диска.
`/dev/sdX` — заполнитель, его необходимо заменить своим устройством.

```sh
sudo dd if=Firmware/out/target/product/zero/aosp-wear-sd.img of=/dev/sdX bs=4M status=progress conv=fsync
sync
```

После `sync` извлеките карту из USB-картридера и вставьте её в слот часов.
Затем выполните:

```sh
./flash sd
```

Компьютер не передаёт содержимое `/dev/sdX` через кабель часов
в режиме SD: карта должна быть физически доступна ESP32 по SPI.

Последняя команда прошивает внутреннее приложение ESP32 и открывает монитор.
Системные данные загружаются с карты; Ctrl+C закрывает монитор, часы продолжают
работать. `./flash pc` выбирает хранение на ПК и запускает сервер.
Ни карта, ни подключённые часы в ходе этой работы автоматически не прошивались.

Отдельный проверенный свежий образ:
`Firmware/out/restored-sd512/aosp-wear-sd.img`. Его можно использовать вместо
образа по умолчанию в команде `dd`; он содержит чистые пользовательские данные.

## Протокол состояния медиаплеера для компаньона

После BLE-сопряжения и включения шифрования доступен необязательный сервис:

- service UUID: `3c7e0001-3b14-4a80-9d3f-178b14740001`;
- writable characteristic UUID: `3c7e0002-3b14-4a80-9d3f-178b14740001`;
- ровно 20 байт: `[version=1, state, position_ms:u32LE, duration_ms:u32LE, reserved:10]`;
- `state`: 0 — остановлено, 1 — пауза, 2 — воспроизведение;
- `position <= duration <= 604800000`; неиспользуемые байты передавайте нулями;
- обновление при изменении состояния и хотя бы каждые 15 с. Через 30 с без данных
  состояние устаревает; отключение Bluetooth сразу его сбрасывает.

Часы экстраполируют позицию только во время полученного состояния «играет»,
останавливают её на конце трека и не меняют её оптимистически по кнопке HID.
Это реализованный интерфейс прошивки, а не готовое приложение Android:
для передачи MediaSession телефона нужен компаньон с разрешением доступа
к уведомлениям/медиасессиям. Название песни и аудиопоток здесь не передаются.

Связь Voice Command с системным ассистентом опирается на
[Linux HID mapping](https://github.com/torvalds/linux/blob/master/drivers/hid/hid-input.c)
и [Android Generic.kl](https://android.googlesource.com/platform/frameworks/base/+/refs/heads/main/data/keyboards/Generic.kl).

Сборки release PC/HID и SD/HID проходят без предупреждений компилятора/линкера.
20 host-тестов проверяют настоящий runtime/Rhai, графику, ввод, таймеры, PIN,

эти испытания. PIN — локальная блокировка интерфейса, а не аппаратная защита
от перепрошивки/извлечения карты.

## Если после записи появляется `android boot error: Card`

В старом логе эта ошибка означала сбой инициализации/получения ёмкости карты
ещё до чтения GPT, а не доказанное отсутствие системы. Успешные `dd` и
`Flashing has completed!` относятся соответственно к записи карты на ПК
и к записи приложения ESP32; они не проверяют чтение карты через слот часов.

Загрузчик сохраняет точную ошибку `SdInit(...)`, а при успехе выводит ёмкость
и тип карты. Ошибка загрузки разделов отдельно отмечается как `SD GPT ERROR`.
Ожидание инициализации ограничено и происходит до операций с A/B-метаданными.
Первопричина сбоя на физической карте ещё не подтверждена.

Для диагностики уже записанную карту повторно стирать не нужно. Карта должна
быть в часах, часы подключены к компьютеру по USB, монитор/сервер из предыдущего
запуска закрыт:

```sh
cd /home/denis/Developer/Android-For-ESP32S3
AOSP_WEAR_SKIP_FIRMWARE_BUILD=1 ./flash sd
```

Сохраните строки от `microSD:` до `android boot error:`. `CardNotFound` или
таймаут команды не различают пустой слот, контакт, питание и распиновку;
`CrcError` и `Transport` указывают на другие ошибки обмена. Не отключайте CRC
и не форматируйте карту в FAT32 для обхода ошибки: загрузчик читает GPT-образ.
Проводка этой сборки: MISO/DO → GPIO7, SCK/CLK → GPIO8,
MOSI/DI → GPIO9, CS → GPIO10; общий GND, питание согласно модулю/слоту.
Несовпадение распиновки с физическими соединениями требует изменения конфигурации.

### Таймаут ACMD41 после успешных начальных команд

Полученный с часов лог показывает `TimeoutACommand(ACMD41_SdSendOpCond)`.
Начальный обмен с картой проходит, но завершить ACMD41 не удаётся. Ошибка может
возникать при ожидании ответа команды либо при повторном получении состояния
idle; прежний тип ошибки не различает эти два случая. GPT и файловая система
здесь ещё не участвуют.

В SD-сборке заменён обычный `ExclusiveDevice`: он поднимал CS между шестью
байтами команды и последующим чтением ответа, а также между отдельными байтами
ответа. `embedded-sdmmc 0.10` выполняет их раздельными вызовами `SpiDevice`.
Новый локальный адаптер `src/sd_spi.rs` удерживает CS в рамках SD-сессии на
полностью выделенной SPI2. Он завершает SPI-запись перед возвратом, отпускает
CS при ошибке/уничтожении и после отпускания передаёт дополнительный байт 0xFF.
Применять этот адаптер на общей шине с другими устройствами нельзя.

CRC остаётся включённым, начальная частота — 100 кГц; разметка и данные карты
не меняются. Два host-теста проверяют потерю ответа при старом управлении CS,
сохранение ответа в новой сессии и отпускание CS при ошибке. Это проверка
поведения транспорта на модели карты; устранение сбоя конкретной физической
карты требует повторного запуска обновлённой SD-сборки. Команда приведена выше.

### Если непрерывная CS-сессия не помогла

На пользовательской карте таймаут повторился и после изменения CS. Поэтому
исправление транспорта не считается подтверждённым решением этого сбоя.
Начальная последовательность теперь выполняется отдельным `src/sd_init.rs`:
CMD0 → CMD8 с полной проверкой R7 → CMD55/ACMD41 с HCS для v2 → CMD58 с проверкой
готовности/OCR → CMD59 CRC_ON → CMD16=512 для карт с байтовой адресацией.
Каждая полная команда начинается с отпускания CS, дополнительного байта 0xFF
и повторного выбора карты; CS остаётся низким до получения ответа/данных.
Стандартный драйвер embedded-sdmmc получает карту только после этой проверки
и затем читает CSD с проверкой CRC. GPT, A/B и работа с блоками не заменены.

Вывод показывает R7, реальные R1 CMD55/ACMD41 при первом опросе, изменении
статуса и каждых 50 опросах, затем OCR. Ожидание готовности: максимум 200 опросов
с задержкой 10 мс (не меньше двух секунд при постоянном idle, плюс время SPI).
Отсутствие R1 в пределах 64 байт, ответ с CRC/illegal-command и постоянный idle
теперь имеют разные ошибки; они больше не сводятся к одному TimeoutACommand.
Неправильный R1 отклоняется сразу, CRC не отключается при ошибке.

Host-тесты проверяют известные CRC7 команд, отложенную готовность SDHC,
порядок CRC_ON, несовпадение R7 и различие idle/нет ответа/ошибки CRC.
На самой карте новый запуск ещё необходим. При повторном сбое нужен весь
фрагмент от `microSD: checked startup v2` до `android boot error:` — он покажет
фактическую стадию и ответ вместо очередного общего таймаута.

### CMD55 возвращает R1=0x07

На карте пользователя startup v2 прошёл CMD8 (R7=00 00 01 AA), затем первая
пара CMD55/ACMD41 вернула 0x01, а следующий CMD55 — 0x07. Предыдущие изменения
не подтвердили устранение сбоя. У 0x07 выставлены idle, erase-reset и illegal
command; это не достаточное основание считать испорченной карту или образ.
Пакет CMD55 проверен по отдельному CRC-вектору: 77 00 00 00 00 65.
[Значения R1 описаны производителем](https://www.analog.com/en/resources/app-notes/an-1443.html).

Startup v3 завершает команду дополнительными восемью тактами при низком CS,
отпускает CS, выдаёт ещё восемь тактов с MOSI=1 и ждёт между опросами с высоким
CS. Частота аппаратной инициализации снижена до 100 кГц. Если приходит R1
с ошибкой, выводятся отправленный шестибайтный пакет и следующие восемь
принятых байт. Ошибка не игнорируется и работа с GPT после неё не начинается.

Для проверки отдельно от аппаратного SPI2 добавлен диагностический
полный дуплекс на GPIO: mode 0, не быстрее 100 кГц, SCK=8/MOSI=9/MISO=7/CS=10,
MISO с внутренней подтяжкой вверх. Он использует те же команды, CRC и карту;
радио, экран и содержимое карты не подменяются. После закрытия монитора:

```sh
cd /home/denis/Developer/Android-For-ESP32S3
AOSP_WEAR_SKIP_FIRMWARE_BUILD=1 AOSP_WEAR_SD_SOFTWARE_SPI=1 AOSP_WEAR_SD_CHECKED_STARTUP=1 ./flash sd
```

В логе будет backend=gpio-mode0 и checked startup v3. Этот режим медленный,
предназначен для сравнения обмена; первая загрузка может заметно затянуться.
Если GPIO заработает, а обычный SPI2 нет, это локализует проблему в аппаратном
пути/его таймингах. Если ошибка сохраняется, остаются общие причины: схема
подключения, питание/контакты, карта или последовательность команд. Потребуются
новый фрагмент лога и проверка физического подключения; успех заранее не заявлен.

Возврат к аппаратному режиму: AOSP_WEAR_SKIP_FIRMWARE_BUILD=1 ./flash sd.
Повторная запись образа карты для этих проверок не нужна. Мини-модуль пользователя
рассчитан на 3,3 В; повышение его питания до 5 В не предлагается.
