# Google Services: телефон, ПК и часы

Реализован MVP из [ТЗ](../App/GOOGLE_SERVICES.md): общий аккаунт, QR-вход с
подтверждением на часах, Gmail readonly, Calendar readonly, поиск и текстовый
просмотр страниц, Google Cloud Translation. Часы обращаются к Gateway по HTTPS
с проверкой CA, имени сервера и времени; HTTP для учётных данных не используется.

**Различайте готовность кода и личную настройку.** Автоматические тесты проверяют
OAuth на синтетических аккаунтах и TLS на настоящем локальном HTTPS-сервере.
Для вашего входа ещё нужны доступный часам HTTPS-адрес, OAuth-настройка и прошивка
устройства. Вход в реальный аккаунт и проверка на ESP32 выполняются после настройки.
Поиск/перевод требуют своих API-ключей. Отправка писем, изменение событий и несколько
аккаунтов относятся к следующему этапу ТЗ; текущий доступ к Gmail/Calendar только на чтение.

## Локально, без домена (ПК или Termux)

Публичный домен, DNS и Caddy не нужны. Gateway работает в вашей Wi-Fi сети;
часы используют `https://IP:8443` с собственным доверенным CA. Вход Google
открывается через `http://localhost:8080` **в браузере на той же машине, где запущен Gateway**.
Интернет всё равно нужен для Google API. Это не установка Google Play Services на часы.

1. Установите Node.js 22.13+, Python 3 и OpenSSL (`pkg install nodejs-lts python openssl` в Termux).
2. В Google Cloud включите [Gmail API](https://console.cloud.google.com/apis/library/gmail.googleapis.com)
   и [Google Calendar API](https://console.cloud.google.com/apis/library/calendar-json.googleapis.com)
   **в том же проекте, где создан OAuth client**, добавьте свой аккаунт в Test users.
   Успешный вход и разрешение доступа не включают эти API автоматически.
   Создайте OAuth client типа **Desktop app** и скачайте JSON вне репозитория.
   Подойдёт и Web client, если у него зарегистрирован точный callback
   `http://localhost:8080/oauth/callback` и JSON скачан заново.
3. Узнайте локальный IPv4 компьютера/телефона. Лучше закрепить его в DHCP роутера.
   Например, для `192.168.1.22`:

```sh
cd GoogleAuthGateway
bash run.sh init "$HOME/Downloads/client_secret.json" --local-ip 192.168.1.22
bash run.sh check
bash run.sh register "Мои часы"
bash run.sh start
```

`register` выводит путь к приватному файлу устройства. Если устройство уже
зарегистрировано, используйте его прежний файл вместо создания нового.
`init` создаёт CA и сертификат с IP в SAN вне Git, с закрытыми ключами в приватной
папке. Повторный запуск сохраняет CA и ключ шифрования аккаунтов.

4. В другом терминале запишите адрес, CA и **тот же** файл устройства в образ часов.
   Остановите `./flash pc` / USB block server перед записью; используйте реальный
   путь к своему образу (носитель не форматируется):

```sh
bash run.sh provision /ПУТЬ/УСТРОЙСТВО.device.json \
  "${XDG_CONFIG_HOME:-$HOME/.config}/aosp-wear-gateway/local-ca.pem" \
  /ПУТЬ/aosp-wear-sd.img --base-url https://192.168.1.22:8443
```

Запустите часы с этим образом и подключите их к той же сети. В приложении Google
начните подключение аккаунта. На компьютере с Gateway откройте
**http://localhost:8080**, выберите запрос часов и войдите в Google. Затем
подтвердите адрес аккаунта **на часах**. Сканировать QR на другом телефоне для
этого режима не требуется: localhost относится к устройству, на котором открыт браузер.

Разрешите входящий TCP 8443 в локальном firewall. Например, для UFW:

```sh
# Подставьте адреса из ./adb wifi-status и ip -4 -brief address.
sudo ufw allow from IP_ЧАСОВ to IP_КОМПЬЮТЕРА port 8443 proto tcp
```

Если часы показывают «Gateway не ответил вовремя», проверьте это правило:
доступность localhost на компьютере не проверяет входящие соединения с часов.
При смене IP часов правило нужно обновить.
Не пробрасывайте 8080 наружу:
он слушает только loopback и принимает только страницы входа, без API устройства.
Проверка TLS, имени/IP и времени на часах остаётся включённой; время часов должно
быть выставлено верно. Сертификат сервера действует год: повторите `init --local-ip`
и перезапустите Gateway для продления. При смене IP также обновите адрес в образе.

Google Calendar/Gmail используют OAuth. Поиск DuckDuckGo не требует ключа.
Для облачного перевода остаётся отдельный ключ из раздела провайдеров.
[Google описывает этот вход через loopback для Desktop apps](https://developers.google.com/identity/protocols/oauth2/native-app).

## 1. Установить и запустить Gateway

Требования: **Node.js 22.13+** со встроенным `node:sqlite`, Python **3.9+** и Pillow
для HTML-писем и превью изображений. `bash run.sh check` проверяет и Python/Pillow.
`npm install` не нужен. На Linux/macOS используйте системные Node/Python.

На Android установите Termux из [F-Droid](https://f-droid.org/en/packages/com.termux/)
или [официального GitHub](https://github.com/termux/termux-app#installation).
Не смешивайте источники приложения и его дополнений.

```sh
pkg update
pkg install nodejs-lts python python-pillow git
termux-setup-storage
git clone --branch Documentation https://github.com/Xopilot-AI-NN/Android-For-ESP32S3.git
cd Android-For-ESP32S3/GoogleAuthGateway
```

В Google Cloud → Google Auth Platform:

1. **Branding**: название и контактный адрес приложения.
2. **Audience**: External / Testing, ваш аккаунт в Test users.
3. В **APIs & Services → Library** включите Gmail API и Google Calendar API.
4. **Clients → Web application**: добавьте точный callback
   `https://ВАШ-ДОМЕН/oauth/callback`. JavaScript origins для этого потока не нужны.
5. Скачайте JSON клиента. Храните его вне checkout; содержимое не отправляйте в чат.

Импорт на телефоне:

```sh
bash run.sh init "$HOME/storage/downloads/client_secret_ВАШ_ФАЙЛ.json" --base-url https://ВАШ-ДОМЕН
bash run.sh check
bash run.sh start
```

На ПК команды те же, только путь к скачанному JSON другой. На Windows:

```powershell
./run.ps1 init "$HOME/Downloads/client_secret_ВАШ_ФАЙЛ.json" --base-url https://ВАШ-ДОМЕН
./run.ps1 check
./run.ps1 start
```

PowerShell-сценарий предоставлен, но на Windows пока не проверялся.
На Windows настройте ACL приватной папки: POSIX-права 0600 не заменяют защиту NTFS.

### HTTPS и доступность

В режиме `--base-url https://ДОМЕН` Node слушает `127.0.0.1:8080`.
Нужен HTTPS reverse proxy на той же машине. Для `--local-ip` он не требуется.
Пример Caddy, замените домен своим и настройте DNS/доступность портов:

```caddyfile
gateway.example.org {
    reverse_proxy 127.0.0.1:8080
}
```

Если Gateway работает на телефоне за мобильным NAT, нужен доступный извне
HTTPS-туннель со стабильным доменом либо сервер. Домен должен разрешаться в сети
часов. При смене домена обновите callback в Google Console, заново скачайте JSON
и повторите `init --base-url ...`. Ключ шифрования и ключи провайдеров сохраняются.

Без `--local-ip` адрес `http://localhost:8080/oauth/callback` используется только для локальной проверки
в браузере того же телефона/ПК. Такой адрес **не подходит часам** и не превращается
в сетевой HTTPS-адрес автоматически.

Если Gateway размещён на телефоне, телефон с сервером нужен постоянно.
Чтобы после входа пользоваться часами без телефона, разместите Gateway на ПК
или сервере. Android может остановить Termux в фоне: разрешите фоновую работу;
скрипт использует `termux-wake-lock`, если команда доступна. Остановка — Ctrl+C.

## Gmail, Контакты, Google Фото и галерея

Gmail показывает единый прокручиваемый список без кнопки «Ещё». При переходе
через край текущей порции письма загружаются автоматически, в обе стороны.
В RAM остаётся одна порция и 32 закладки; более старые страницы при необходимости
перечитываются с сервера. Размер почтового ящика не задаёт расход ОЗУ часов.

HTML-письма преобразуются на Gateway в абзацы, списки и текст ссылок; JavaScript,
формы, CSS и встроенные браузеры не исполняются. Картинки (CID, data URI, публичный
HTTPS) идут отдельными блоками в порядке письма, по мере чтения колёсиком.
Gateway уменьшает их до 108×80, переводит в RGB565 и сжимает zlib; часы показывают
превью до 216×160. Размер одного декодированного превью — не более 17 280 байт.
Картинки больше 2 МиБ, SVG и повреждённые изображения пропускаются, текст остаётся
читаемым. Внешние картинки загружаются без Google-токенов, cookie и Referer;
частные IP/DNS и небезопасные перенаправления блокируются. Невидимые пиксели,
явно отмеченные размером 1×1 в HTML, пропускаются.

Для Python/Pillow используйте пакет вашей системы, например `python-pillow`
на Arch Linux и в Termux. Проверьте установку командой `bash run.sh check`.

«Контакты Google» использует [People API](https://console.cloud.google.com/apis/library/people.googleapis.com).
Включите его в том же Cloud-проекте, затем откройте приложение → «Доступ Google»
→ «Разрешить в Google». На часах подтвердите аккаунт и **контакты** в списке доступа.
Приложение читает имена, телефоны и email; изменение контактов не выполняется.

В галерее есть два источника: «На часах» и «Google Фото». Локальная галерея
обновляет каталог после передачи файлов; возврат из фото отменяет незавершённое
чтение и освобождает превью. Ошибка декодирования не оставляет старую картинку
под именем нового файла.

Google Фото использует официальный **Photos Picker API**, а не полный доступ
к медиатеке. Включите [Photos Picker API](https://console.cloud.google.com/apis/library/photospicker.googleapis.com),
затем «Галерея» → «Google Фото» → «Доступ Google» и разрешите выбранные фото.
После подтверждения на часах нажмите «Выбрать фото»: сканируйте QR или откройте
`http://localhost:8080` на компьютере с Gateway и перейдите по ссылке выбора.
В Google Фото выберите снимки и нажмите «Готово». Часы сами обновят список;
откройте нужную фотографию колёсиком. Видео не загружаются. Сессия/ссылки Picker
ограничены Google по времени: для нового выбора снова нажмите «Выбрать фото».
[Изменения API Google Фото](https://developers.google.com/photos/support/updates),
[Picker API](https://developers.google.com/photos/picker/guides/get-started-picker).

## 2. Подключить поиск и перевод

Поиск уже использует **DuckDuckGo** и не требует API-ключа, регистрации или
подписки Brave. На Gateway разбирается [официальная HTML-версия DuckDuckGo](https://duckduckgo.com/duckduckgo-help-pages/features/non-javascript),
а на часы отправляются пять результатов и короткие описания. Это HTML-адаптер,
не официальный API полной поисковой выдачи. Результат открывается в прежнем
ограниченном текстовом просмотрщике с проверкой публичного HTTPS-адреса.

DuckDuckGo может вернуть CAPTCHA/ограничение именно серверному клиенту, даже
если тот же запрос открывается в обычном браузере. Тогда часы показывают
«DuckDuckGo просит проверку». Код не решает и не обходит CAPTCHA, не подменяет
её пустым списком и выдерживает паузу 60 секунд перед новым внешним запросом.
Одинаковые запросы одного устройства кешируются на минуту; кеш ограничен.
При смене HTML-разметки возвращается ошибка ответа, а не вымышленные ссылки.

Для перевода включите [Cloud Translation API](https://console.cloud.google.com/apis/library/translate.googleapis.com),
подключите billing проекта и создайте API key с ограничением **Cloud Translation API**.
Здесь используется Basic v2, поддерживающий ключи API.
[Официальная настройка Translation](https://docs.cloud.google.com/translate/docs/setup),
[поддержка API keys](https://docs.cloud.google.com/translate/docs/authentication).
Откройте приватный файл `~/.config/aosp-wear-gateway/providers.json` и заполните
только ключ переводчика. Ключи не вставляйте в исходники, команды терминала или чат.

Google Cloud Translation использует отдельный API-ключ проекта, включённый
Cloud Translation API и настроенные квоты/биллинг; OAuth личного Gmail ему не нужен.

Создайте **вне Git**, например в приватной конфигурационной папке, JSON:

```json
{
  "google_translate_api_key": ""
}
```

Старое поле `brave_search_api_key`, если осталось в приватном JSON, игнорируется.
Заполните ключ переводчика локально и импортируйте файл:

```sh
bash run.sh providers "$HOME/.config/aosp-wear-gateway/providers.json"
```

Работающий Gateway автоматически перечитает ключи после импорта; перезапуск не нужен.
Пустой/отсутствующий ключ отключает облачный перевод; Gmail/Calendar продолжают работать. На часах появляется понятная ошибка
настройки вместо вымышленных результатов. Офлайн-словарь RU/EN остаётся доступен
переводчику без сети; облачный перевод поддерживает RU/EN и автоопределение → EN/RU/DE/FR/ES.

Локальные суточные лимиты сохраняются в SQLite, включая перезапуск сервера:

| Операция | На устройство | На весь Gateway |
|---|---:|---:|
| Запросы поиска | 100 | 200 |
| Чтение страниц | 100 | — |
| Символы перевода | 5 000 | 50 000 |

Ошибки провайдера тоже расходуют локальную квоту. Эти ограничения не заменяют
квоты и контроль расходов в кабинете провайдера. Один перевод — до 1024 символов;
ввод на часах ограничен 1024 UTF-8 байтами. История писем и текстов на серверный
диск не записывается. Для чтения веб-страниц запрещены локальные/служебные адреса,
проверяются все redirect и DNS, нет JavaScript, вложений и загрузки внешних ресурсов.

## 3. Передать настройки часам

Обновите **и нативную прошивку, и системный образ**: старые бинарники не содержат
TLS-клиента/новых экранов. Приватные значения не вшиваются в исходники или ELF.
Для сборки прошивки в новом клоне сначала выполните `git submodule update --init --recursive`
из корня проекта; запуск самого Gateway подмодулей не требует.
Нужен остановленный GPT-образ, который часы будут использовать в PC/SD-режиме.
Перед записью остановите `usb_block_server.py`; скрипт проверит его файловую блокировку.

Во второй сессии терминала из папки Gateway:

```sh
bash run.sh register 'Мои часы'
bash run.sh ca
```

`register` напечатает путь приватного device JSON. `ca` подключается к HTTPS Gateway
с обычной проверкой доверия Node и экспортирует соответствующий **публичный CA**
в `~/.config/aosp-wear-gateway/gateway-ca.pem`. Непроверенный сертификат не импортируется.
Для своего внутреннего CA передайте его публичный PEM отдельно; проверки TLS не отключайте.

```sh
bash run.sh provision '/полный/путь/устройства.json' \
  "$HOME/.config/aosp-wear-gateway/gateway-ca.pem" \
  '/полный/путь/aosp-wear-sd.img' --base-url https://ВАШ-ДОМЕН
```

Запись конфигурации поддерживается на Linux/macOS/Termux. На Windows используйте
WSL для этого шага: инструмент отказывает без совместимой файловой блокировки.
Проверяются CRC/границы GPT, чужие данные в резервных слотах и readback.
Перезаписывается только альтернативная копия конфигурации ZPager **76/77**;
остальные разделы и пользовательские файлы сохраняются. Слоты **78/79** зарезервированы
для постоянного состояния выхода. Один CA — максимум 3000 байт, запись — максимум 4080 байт.

Образ теперь содержит **секрет устройства**. Храните его приватно; не загружайте
в Git/облако вместе с исходниками. Пароль Google, Google access/refresh tokens,
OAuth client secret и API-ключи в образ часов не передаются.

Запустите PC block server с этим образом либо запишите подготовленный образ на
карту обычным способом проекта. Перезапустите часы, подключите Wi-Fi и дождитесь
синхронизации времени. Без корректного времени TLS отказывает, а не пропускает проверку.

Gateway может оставаться на телефоне, а образ — на ПК. Для такого варианта передайте
на ПК только приватный device JSON и публичный CA через USB или SSH/SFTP и выполните
`provision` там. OAuth JSON, `STORE_KEY` и ключи API на ПК для этого не нужны.

## 4. Войти на часах и проверить приложения

1. **Настройки → Аккаунты → Google**. Выберите Calendar, Gmail или оба сервиса.
2. Сканируйте QR телефоном. Ссылка живёт пять минут.
3. Войдите на официальной странице Google и выберите разрешения.
4. На часах проверьте показанный адрес и разрешения, нажмите **Подтвердить**.
   Одного сканирования QR недостаточно. Отмена и PIN-блокировка прекращают локальную попытку.
5. Откройте Calendar/Gmail и обновите данные. После перезапуска сессия обновляется
   ключом устройства, пока серверная привязка и разрешения действуют.

Управление:

- **Calendar:** месяц → колесо меняет месяц, нажатие загружает события. Список и
  карточка содержат фактические даты/смещения и целодневные события. API раскрывает
  повторения. Точки относятся к событиям загруженной страницы; «Ещё» получает следующую.
- **Gmail:** три письма на страницу, тема/отправитель, карточка с датой и plain text.
  Колесо прокручивает текст; нажатие загружает следующую серверную страницу, если она есть.
  Поворот вверх в начале страницы возвращает предыдущую. Вложения не открываются.
- **Поиск:** запрос → результаты DuckDuckGo → браузер с HTML, ссылками и сжатыми изображениями.
  Страница должна быть публичной HTTPS HTML/plain text, до 256 КиБ. Результат-ссылка
  привязана к устройству и действует пять минут; затем обновите поиск.
- **Переводчик:** введите фразу, выберите направление, подтвердите ввод.
- **Аккаунт → Синхронизировать** обновляет разрешённые Gmail/Calendar.
  **Выйти** требует отдельного подтверждения, очищает кэш и сохраняет состояние выхода.
  Без сети серверная отвязка выполняется после восстановления связи; перезапуск
  не возобновляет вход автоматически. Новый вход снова требует подтверждения.

Кэш только в RAM и помечается офлайн. После холодного запуска без сети личные данные
не восстанавливаются из файлов. Поддерживаются ASCII, кириллица и Latin-1/Œ/œ;
символы вне шрифта отображаются знаком замены, исходный UTF-8 в кэше сохраняется.
PIN защищает UI и доступ сервисов; это не шифрование всей microSD от физического чтения.

## Диагностика и приватность

Конфигурация: `$XDG_CONFIG_HOME/aosp-wear-gateway/config.env`, по умолчанию
`~/.config/aosp-wear-gateway/config.env`. База/device/session JSON:
`$XDG_STATE_HOME/aosp-wear-gateway`, по умолчанию `~/.local/state/aosp-wear-gateway`.
В Termux используйте внутренний HOME приложения. На POSIX папки — 0700, конфигурация
и база — 0600; OAuth-токены зашифрованы AES-256-GCM с привязкой к устройству.
Не меняйте `STORE_KEY` вручную: старые токены станут нечитаемыми.

Google-данные/ключи не попадают в серверные console logs. Журнал часов сообщает
только общие состояния и коды TLS, без запросов, писем или заголовков авторизации.
Ошибка scope требует нового согласия; 401/`invalid_grant` — повторного входа;
429/локальная квота — ожидания. В Testing Google может требовать повторную авторизацию
через семь дней для этих scopes; это не неисправность часов.

Перед публикацией из корня проекта:

```sh
python3 tools/install_git_guard.py
python3 tools/check_public_files.py
```

Hooks проверяют индекс; при клонировании их нужно устанавливать отдельно.
Секреты, базы, образы, личные фотографии и логи публиковать нельзя.
При утечке OAuth/API-ключ отзывается у провайдера; удаление файла не очищает историю Git.

Проверки Gateway: `bash run.sh test` (Node и Python; для CA-теста нужен OpenSSL).
Проверки настоящего Rust/TLS-клиента из корня:

```sh
bash Firmware/tools/run_runtime_tests.sh Firmware/out/google-services-build/aosp-wear-sd.img
```

Нужны системные Clang/libclang, CMake, OpenSSL, Node и Rust stable.
Скрипт выбирает host LLVM через `llvm-config`, чтобы Xtensa libclang не использовался
для x86_64-тестов. Записи тестов хранения идут только в RAM-overlay, исходный образ не меняется.

Официальные материалы: [OAuth web-server flow](https://developers.google.com/identity/protocols/oauth2/web-server),
[Gmail scopes](https://developers.google.com/workspace/gmail/api/auth/scopes),
[Cloud Translation](https://docs.cloud.google.com/translate/docs/basic/translating-text),
[DuckDuckGo HTML](https://duckduckgo.com/duckduckgo-help-pages/features/non-javascript).


### Браузер HTML на часах

В меню есть отдельный «Браузер», он же открывает результаты поиска.
Gateway разбирает HTML в ограниченные смысловые блоки; часы рисуют их под экран
240×280, поддерживают историю, переходы по ссылкам, якоря, обновление и две темы.
Изображения загружаются по нажатию и передаются как RGB565 + zlib до 108×80.
Работают публичные HTTPS-сайты; Google OAuth/платный API не нужны.
JavaScript, полноценная CSS-вёрстка, формы и вход на сторонние сайты не реализованы.
Подробности: [приложение Браузер](../App/system/app/Browser/README.md).

После обновления исходников перезапустите `bash run.sh start`, чтобы появились
`POST /api/v1/browser/open` и `GET /api/v1/browser/documents/:id`
(изображения: `/api/v1/browser/documents/:id/images/:index`). Все маршруты требуют
учётные данные устройства; документы другого устройства недоступны.
